# 套房租金管理系統備份機制

最後更新：2026-06-10

這份文件的目的，是讓系統資料可以在誤操作、電腦故障、程式改壞、或 Supabase 資料庫異常時，有清楚的恢復方式。

## 備份分成三層

### 1. 程式碼備份

目前程式碼已放在 GitHub：

- `https://github.com/wcy1993216-hub/rental-suite-manager.git`

Vercel 也會保留每次部署紀錄。若某次更新後系統壞掉，可以先到 Vercel 使用 Rollback 回到上一版。

重要原則：

- 程式碼可以放 GitHub。
- `.env.local`、Supabase key、資料庫密碼不可放 GitHub。
- 租客資料、對帳單、資料庫匯出檔不可放公開 GitHub。

### 2. 資料庫備份

正式資料存在 Supabase PostgreSQL，不在本機電腦。

Supabase 官方備份位置：

1. 打開 Supabase Dashboard。
2. 進入本系統的專案。
3. 左側選單進入 `Database`。
4. 找到 `Backups`。

依 Supabase 官方文件，Pro、Team、Enterprise 專案會有每日資料庫備份；Free 專案建議定期用 Supabase CLI 匯出資料。方案保留天數可能會變動，實際以 Supabase Dashboard 顯示為準。

建議做法：

- 如果系統正式營運，建議 Supabase 至少使用 Pro 方案，讓資料庫有每日備份。
- 每次大量匯入 Excel、刪改大量房間或租約前，先確認 Supabase 有可用備份。
- 如果目前是 Free 方案，至少每月底手動匯出一次資料庫。

### 3. 每月對帳留檔

每月底對帳完成後，請在系統裡做業務留檔。

建議流程：

1. 進入 `每月收租表`。
2. 選擇要結算的月份。
3. 檢查匯款、現金、未收、異常金額。
4. 點選 `匯出本月對帳單`。
5. 下載後存成固定檔名，例如：
   - `2026-06_套房租金管理系統_對帳單.xlsx`
6. 確認無誤後，使用 `月結鎖定`。

建議保存位置：

- 電腦本機一份。
- OneDrive、Google Drive 或外接硬碟一份。

不要只存在下載資料夾，因為之後很容易找不到。

## 建議備份頻率

### 每月底固定做

- 匯出本月對帳單。
- 月結鎖定。
- 把 Excel 對帳單放到雲端硬碟。

### 每次大量修改前做

例如：

- 大量匯入 Excel。
- 一次新增很多房間。
- 一次更換很多租客。
- 要調整資料庫 schema。

先確認 Supabase Dashboard 裡有可還原的備份，再開始操作。

### 每次改系統功能後做

程式修改完成後：

1. 本機執行建置確認。
2. 提交到 GitHub。
3. 等 Vercel 自動部署完成。
4. 打開正式網址確認登入與主要頁面正常。

## 手動匯出資料庫

如果目前使用 Free 方案，或想在重大修改前自己留一份完整資料庫，可以用 Supabase CLI 匯出。

Supabase 官方建議分成三份：

```powershell
supabase db dump --db-url "[CONNECTION_STRING]" -f roles.sql --role-only
supabase db dump --db-url "[CONNECTION_STRING]" -f schema.sql
supabase db dump --db-url "[CONNECTION_STRING]" -f data.sql --use-copy --data-only -x "storage.buckets_vectors" -x "storage.vector_indexes"
```

`[CONNECTION_STRING]` 要到 Supabase Dashboard 的 `Connect` 裡取得，通常選 `Session pooler` 連線字串，再把 `[YOUR-PASSWORD]` 換成資料庫密碼。

注意：

- 匯出的 `data.sql` 會包含租客姓名、電話、收租紀錄，不能放公開 GitHub。
- 建議放在雲端硬碟的私人資料夾，例如：
  - `OneDrive/套房租金管理系統備份/2026-06-30/`

## 還原時怎麼做

### 情況 1：程式更新後壞掉

先用 Vercel Rollback：

1. 打開 Vercel。
2. 進入 `rental-suite-manager` 專案。
3. 找到 `Deployments`。
4. 選擇上一個正常版本。
5. 執行 Rollback。

這只會恢復程式，不會更動 Supabase 資料。

### 情況 2：資料被誤改

如果只是少量資料錯誤，先不要直接還原整個資料庫。

建議順序：

1. 先看系統的 `操作紀錄`。
2. 確認是哪一筆資料被改。
3. 如果能手動修回來，就手動修正。
4. 如果資料大量錯誤，再考慮 Supabase Database Backup 還原。

### 情況 3：整個資料庫需要還原

使用 Supabase Dashboard：

1. 進入 Supabase 專案。
2. 打開 `Database > Backups`。
3. 選擇出事前最近的一份備份。
4. 確認還原。

注意：

- 還原期間系統可能暫時不能用。
- 還原會回到備份當時的資料狀態，備份後新增的資料可能會消失。
- 如果不確定，先不要按還原，先詢問懂系統的人協助。

## 保存期限建議

- 每月對帳單：至少保存 5 年。
- 每月資料庫手動匯出：至少保存最近 12 個月。
- 年底總備份：永久保存或至少保存 5 年。

## 最重要的三句話

1. 平常用 Supabase 備份保護資料庫。
2. 每月底匯出對帳單，留一份人看得懂的檔案。
3. 資料備份不能放公開 GitHub。
